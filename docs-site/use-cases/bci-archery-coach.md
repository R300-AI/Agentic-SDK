# BCI 射箭教練

這個實施例把 Agentic SDK 用在 BCI 輔助的射箭教練情境。核心目標不是取代教練，而是把腦波、姿態或訓練紀錄等訊號整理成可操作的訓練建議，幫助選手與教練更快發現注意力、疲勞與出手穩定性的變化。

## 場景目標

BCI 射箭教練通常要處理的不只是語言輸入，而是多來源訊號的綜合理解。例如選手的腦波專注指標、心率變化、拉弓穩定度、出箭時間點與過往訓練紀錄，可能都要被整理成同一輪回饋。系統的責任是把這些訊號轉譯成訓練語言，而不是直接替代運動決策。

## 建議流程拆法

在這個場景中，`Perceive` 應把教練提問、選手主觀回饋與即時感測資料整理成一致的訓練上下文。`Plan` 再決定這一輪要不要先查歷史訓練紀錄、BCI 指標說明或動作模式知識。`Retrieve` 主要面向訓練記錄、選手基線、感測器事件與教練標註。`Action` 要產出短而清楚的訓練建議，例如要先休息、調整呼吸節奏，或回看特定一組射擊。若回饋不夠穩定，`Reflect` 可要求系統先補查資料再重新回答。

## 建議資料來源

- BCI 指標：專注度、疲勞度、異常波段變化。
- 動作資料：拉弓穩定度、放箭瞬間抖動、姿態感測、心率或呼吸節奏。
- 歷史訓練：每組成績、教練標註、比賽前後狀態、恢復紀錄。
- 安全規則：疲勞門檻、裝備檢查、訓練中止條件。

## 推薦模組組合

- `Perceive`：若輸入來源較複雜，建議使用可整合多欄位上下文的 `LLMBasedPerceive`，而不是只用單一句子入口。
- `Plan`：用 `ReActPlan` 決定是先查歷史紀錄、即時感測事件，還是直接輸出建議。
- `Retrieve`：此場景通常更適合 `SemanticRetrieve`，因為你需要回查相似訓練段落、選手歷史模式與教練標註。
- `Action`：用 `CompletionAction` 把訊號翻成教練可操作的短指令或摘要。
- `Reflect`：建議加入 `ReflexionReflect`，避免系統在資料不足時過度解讀 BCI 訊號。

## 一輪對話示例

教練可能會問：「這一組為什麼後三箭明顯失準？」系統先在 `Perceive` 整理這個問題與當前感測上下文，`Plan` 判斷需要先回查該組的 BCI 專注指標、心率與放箭穩定度，`Retrieve` 取回資料後，`Action` 輸出像「後三箭前專注度下降、放箭抖動增加，較像疲勞累積而非純技術走樣」這種回饋。若證據不足，`Reflect` 應要求系統回到 `Retrieve` 補查相鄰訓練組或歷史基線，而不是直接下判斷。

## 落地注意點

這個場景最大的風險是把相關性誤寫成因果。BCI 與動作資料可以輔助判讀，但不應被寫成醫療級或絕對性的結論。因此實作時應優先定義資料可信度、教練覆核流程與安全中止條件，並讓 `Action` 的語氣保持在「建議」「觀察到」「可優先檢查」這種可被人類教練接手的層級。
