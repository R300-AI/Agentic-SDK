# BCI 射箭教練

示範導入案例：看 Agentic SDK 如何把 BCI 訊號、動作資料與教練判讀流程整合成可操作的訓練輔助系統。

**問題**  高強度射箭訓練同時依賴專注力、動作穩定度與教練經驗，資料來源多而分散，單靠人工很難在每一輪訓練中快速整理出一致的回饋。  
**解法**  以 Agentic SDK 建立多模態訓練 workflow，讓訊號理解、歷史回查、建議輸出與反思補查都能被拆成可治理的 agent 流程。

## 把多模態訓練訊號變成可執行的教練語言

在 BCI 輔助射箭訓練裡，真正困難的從來不是把資料收進來，而是把資料翻譯成教練和選手能採取行動的語言。選手每一輪射擊的背後，可能同時包含腦波專注指標、疲勞訊號、姿態穩定度、放箭瞬間抖動、心率變化與歷史訓練記錄。這些訊號如果只是被動儀表板，價值有限；但若能在訓練現場快速轉譯成「為什麼這一組掉點」「下一組應優先調整什麼」，就會變成實際可用的教練輔助能力。

Agentic SDK 在這個場景裡的角色，是把這種多來源訊號判讀流程拆成一條可維護的 agent workflow。系統先理解本輪問題，再決定要不要回查歷史紀錄或即時感測事件，最後輸出短而清楚的訓練建議。若證據不足，流程還能要求自己回去補查，而不是過早下結論。

## 射箭訓練的難點在於資料很多，但上下文更重要

BCI 射箭教練面對的問題，不像一般問答系統那樣只需要處理一句文字。教練可能問的是「這一組為什麼後三箭明顯失準」，但真正的答案不在問題本身，而在訓練當下的上下文。系統要能把教練提問、選手主觀回饋、專注度曲線、疲勞指標、出箭時序與歷史基線放進同一輪理解。

這種場景如果沒有明確流程，很容易陷入兩種失敗模式。第一種是資料很多，但系統只能逐欄回報，看不到關聯。第二種是模型過度生成，看似給出完整解釋，實際上只是把相關性誤寫成因果。前者讓系統沒有教練價值，後者則可能直接傷害訓練判斷。

## Agentic SDK 如何把教練判讀流程系統化

在這個示範案例裡，`Perceive` 先把教練提問、選手主觀回饋與即時感測資料整理成一致的訓練上下文。`Plan` 再決定這一輪是否需要先回查歷史訓練紀錄、BCI 指標說明或動作模式知識。`Retrieve` 面向的是訓練記錄、選手基線、感測器事件與教練標註。`Action` 的責任不是生成一大段報告，而是輸出一段教練可以立刻使用的建議，例如優先休息、先檢查節奏、回看某一組的放箭穩定度。若回饋不夠穩定，`Reflect` 可要求系統先補查資料，再重新整理答案。

這種拆法的價值在於，每個能力點都能單獨優化。當感測資料種類增加時，可以先擴充 `Perceive` 的上下文整理方式。當回查能力不足時，優先升級 `Retrieve`。當輸出的建議太模糊，則調整 `Action`。這讓整個訓練輔助系統不是被綁在單一 prompt 上，而是一條可觀察、可演進的流程。

## 從即時判讀走向可追溯的訓練回饋

想像教練在一組訓練後問：「這一組為什麼後三箭明顯失準？」Agentic SDK 不會只盯著成績，而是先把這個問題與當前感測上下文整理成同一輪判讀任務。`Plan` 判斷需要回查該組的 BCI 專注指標、心率與放箭穩定度，`Retrieve` 取回資料後，`Action` 再輸出像「後三箭前專注度下降、放箭抖動增加，較像疲勞累積而非純技術走樣」這種可操作回饋。

重點不是它講得多像人，而是它能不能把訓練資訊壓縮成教練可用的決策提示。若資料不足，`Reflect` 應該把流程拉回 `Retrieve`，補查相鄰訓練組、歷史基線或既有標註，而不是直接把猜測包裝成答案。這也是 Agentic SDK 比單純 completion 更適合這類場景的原因。

## 為什麼這類高風險判讀場景適合 Agentic SDK

在 BCI 射箭教練這種高上下文密度場景裡，系統不能只追求「會回答」，而要追求「回答是怎麼形成的」。Agentic SDK 的優勢正在於它把理解、決策、回查、生成與反思拆開，讓團隊可以逐步驗證每個環節的可信度。對訓練科技團隊來說，這也意味著系統可以先從教練輔助起步，之後再逐步擴充到訓練報告、自動標註、疲勞監測與恢復建議。

實作上，這種場景通常較適合 `LLMBasedPerceive + ReActPlan + SemanticRetrieve + CompletionAction + ReflexionReflect` 的組合。原因很直接：輸入來源多、上下文複雜，而且對錯誤判讀的容忍度低。這不是最便宜的組合，但通常是最符合場景風險的組合。

## 從訓練輔助走向可規模化的教練平台

一旦這條流程穩定下來，BCI 射箭教練就不只是一個問答功能，而會變成訓練平台的核心協調層。它可以往上接更多感測來源，往下接訓練報表、教練標註、比賽前後比較與安全中止規則。也就是說，Agentic SDK 在這裡扮演的不是單一模型接點，而是把感測、知識、判讀與回應串起來的系統骨架。

這個案例最需要被強調的，是誠實的邊界。BCI 與動作資料可以輔助判讀，但不應被寫成醫療級或絕對性的結論。因此真正成熟的導入方式，不是讓系統看起來像全知教練，而是讓它成為一個會在必要時回查資料、保留不確定性、並把判讀交還給人類教練的 agent workflow。
