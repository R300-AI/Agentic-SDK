# 20. 記憶屬於它是從誰身上累積起來的

Date: 2026-09-23

## Status

Accepted

延伸 ADR-0011、ADR-0012。

## Context

「承接前文問答」交付之後，「跨對話」跨到哪裡從來沒有被決定過。實測的結果是跨到同一個 Agent 的所有人：第二段對話的系統提示裡會出現第一段合成出來的主題，而搜尋查得到第一段的原始紀錄，原文。

一台放在現場、多個人輪流用的 Agent，因此會把前一個人的訂單號碼、姓名講給下一個人。這件事沒有人選過——ADR-0011 說檔案按流程的名字分、同一條流程的各段對話共用，ADR-0012 說原始紀錄留著且搜尋得到，兩者都成立，而「各段對話」包不包含別人的對話，兩份都沒寫。

規格的 User Story 3 寫的是「我希望 agent 記得**我**上一次講過的事」。那句話預設了「我」，而實作裡沒有「我」這個概念。

## Decision

**記憶多一個維度：它是從誰身上累積起來的。** `MemoryEntry.user_id`，跟著 `workflow_name`／`session_id` 一起走。`Workflow.run()` 與 `stream()` 收一個 `user_id`。

**判斷規則是單純的相等比對：`entry.user_id == self.user_id`。** 四種情形都對：
- 兩個各自被識別的人，只讀得到自己的。
- 沒有被識別的執行讀不到被識別的人的東西，它寫的東西那個人也讀不到——兩個方向都是交給陌生人。
- 什麼身分都沒有的程式（直接用 SDK 的人）擁有者是 `None`，它寫的全部都是它自己的，行為和以前一樣。

第一版寫的是「任一邊沒有身分就一律讀不到」，結果是 SDK 的預設用法整個失效——37 個既有測試倒掉指出了這件事。要擋的是兩個**不同**的人互相看到，不是「沒有人」看不到自己的東西。

**擋在 `mine()` 這一個方法，其他任何地方都不直接讀 `_entries`。** 搜尋、索引、合成、對話、刪除、清除，全部經過它。

第一版是在各個呼叫端各擋一次，結果如同這條決議預期的：忘記擋的那幾個就是外洩。審查實測抓到四個——**別人可以只憑識別碼刪掉你的主題**；兩個人共用同一個對話識別碼時，對話原文直接出現在另一個人的提示詞裡；合成時會讀到別人的主題內容、送進自己的端點、再覆蓋掉對方記得的東西；`clear()` 清掉所有人的。前三個是我把這條決議寫進 ADR 之後、程式卻沒有照著做。

**Playground 的身分有兩種強度。** AI Hub 帳號是真的身分，換一台機器還是同一個人。匿名試用沒有身分，改成每一個瀏覽器發一個自己的識別碼，存在那個瀏覽器的 session 裡。它刻意比較弱：同一個人換一個瀏覽器要重來——那是錯的時候該往的方向。它保證的只有一件事：不會把前一個訪客的記憶交給下一個。

**身分由路由傳進服務，服務不自己去拿請求情境。** 這一點犯了兩次（`memory_admin` 與 `runner_service`），兩次都是整組測試倒掉才發現：一個會去拿當下請求的服務，從別的地方就呼叫不了。

**記憶面板顯示的是這個 Agent 記得「讀它的人」的什麼。** 一個人的訂單號碼不是下一個人的事，而面板正是它最會被攤開來看的地方。

考慮過並否決的做法：

- **維持現狀，只在建構器寫明。** 適用在內容本來就共用的場域，但那要每一個部署的人自己判斷，而預設值會是錯的那一邊。
- **索引與搜尋也按對話過濾。** `CrossContextMemory` 只剩下跨重啟，跨不了對話——那和 `InContextMemory` 只差一件事，#34 與 #37 的價值幾乎歸零。
- **匿名試用一律沒有跨對話記憶。** 比較安全，但匿名試用是大多數人第一次看到這個功能的地方，關掉等於那個功能在試用時形同不存在。

## Consequences

**已經寫在磁碟上的記憶沒有擁有者，而且留在原地。** 它們的 `user_id` 是 `None`，所以任何被識別的人都讀不到。猜一個擁有者就是把它交給第一個來問的人。代價是這次之前累積的記憶，對登入後的使用者等於不存在。

**同一個人換一個瀏覽器，匿名試用會重來。** 那是匿名的定義，不是缺陷。要接得下去就登入。

**`MemoryEntry` 多一個欄位，檔案的 front matter 也多一行。** 舊檔讀起來是 `None`，不需要轉檔。

**`copy_for_run()` 要帶著擁有者。** 這一類「複製的時候漏掉設定」在 #34 發生過一次，那一次的後果是功能在正式環境從來沒有跑過。這次兩個 `copy_for_run` 都補上了。

**搜尋的過濾發生在計分之前。** 別人的紀錄根本不進候選集合，而不是先算分再濾掉。

**`clear()` 的意思變成「清掉我看得到的」。** 對擁有者是 `None` 的程式沒有差別——它寫的全部都是它自己的。對多人共用的部署，它不再是一個誰都能按的總清除。

**刪一個不屬於你的主題，回報的是「找不到」而不是「不准」。** 哪些識別碼存在於別人的記憶裡，本身就是別人的事。

**`workflow_id` 仍然沒有被用在任何過濾上。** 它跟著每一筆寫下去，但沒有人讀它。這一次沒有動它。
