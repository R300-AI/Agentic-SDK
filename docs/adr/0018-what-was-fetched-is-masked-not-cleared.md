# 18. 查過、叫過的東西遮蔽，不清除

Date: 2026-09-23

## Status

Accepted

延續 ADR-0016。

## Context

ADR-0016 定了請求裝不下時放掉什麼：這一輪之前的對話，最舊的先放。那一版只有兩種手段——記憶自己合成，然後整則訊息放掉。

整則放掉對某幾種內容代價特別高。一次工具回覆、一份被取用的技能文字，兩者都很長、都是這個執行去取回來的、而且通常只在取回來的那一輪有用。它們在後面幾輪仍然完整地擺在模型面前，佔的位置和一段長答案一樣多。

但直接放掉它們會製造一個新問題。規劃讀對話是為了知道哪些事已經試過；一段看不出查過那件事的對話，會讓規劃再查一次。端點小到需要省這些位置的時候，重查正是最貴的那個錯誤。

Codex 的做法是 Observation Masking，和壓縮並用。

## Decision

**細節拿掉，紀錄留著。** 那一則訊息不會消失，它換成一句說明它原本是什麼——哪一個工具、哪一份技能。規劃因此仍然看得到這件事做過。

**遮蔽的對象是這個執行取回來的東西，不是人說的話。** 三種：角色是 `tool` 的回覆、帶著技能標記的那一則（ADR-0006 寫的取用）、以及帶著 `tool_call_submission` 來源的那幾則。使用者說的話與 Agent 給的答案永遠不遮——遮了會變成一段宣稱有人說過話、又不肯說是什麼話的對話。

**這一輪不動。** 「這一輪」沿用 ADR-0016 的定義。正在寫的那個答案就是根據剛才取回來的東西寫的，遮掉它等於拿空的去回答。檢索證據同樣不動，它在系統那一層，那一層不放也不遮。

**沒有固定界線、沒有固定輪數，用同一個門檻。** 請求裝不下才開始遮，從最舊的往回，裝得下就停。一個長不起來的執行因此完全不會付這個代價。

**順序是：合成、遮蔽、放掉。** 記得住自己的記憶先把最舊的合成成主題；還是裝不下就遮蔽取回來的細節；再裝不下才整則放掉。遮蔽比放掉便宜——留下的紀錄擋掉一次重查——所以它排在前面。

**遮蔽在組訊息那一層做，不在記憶層。** 合成需要記憶記得住自己，遮蔽不需要：`InContextMemory` 壓不了但遮得了。這兩個類別沒有共同的基底，唯一都會經過的地方是組訊息的出口，所以判斷放在那裡。規格寫的「壓不了就只做遮蔽與截斷」因此是自然成立的，不必另外偵測能力。

考慮過並否決的做法：

- **直接清除。** 規劃看不出查過，於是再查一次——工單指名了這一點。
- **固定遮蔽 N 輪以前的內容。** N 是編出來的；而且短對話會付一個它不需要付的代價。
- **在記憶層遮蔽。** 兩個記憶類別沒有共同基底，會變成同一段邏輯寫兩次。
- **連使用者說的話一起遮。** 那段對話會變得沒有人看得懂。

## Consequences

**遮蔽靠訊息與 turn 一一對應。** 組訊息的那一層拿 `conversation.turns` 來看每一則原本是什麼——訊息本身只有 role 與 content，metadata 在轉換時就掉了。數目對不上時就整個不遮，寧可送出去比較大的請求，也不要遮錯一則。

**技能的 metadata 鍵移到 `agentic_sdk/memory/in_context.py`。** 組訊息的那一層要讀它，而記憶不能 import 模組。它本來就是 turn 的 metadata 鍵，放在定義 turn 的地方才對。規劃模組改成從那裡 import，`agentic_sdk.modules.plan` 與 `agentic_sdk.memory` 兩個公開名字都還在。

**那個鍵因此離開了 `.github/CODEOWNERS` 指給技能包那一組的路徑。** 它現在在記憶單元的路徑底下，將來改它的名字不會自動送到原本那一組面前。這裡只記下來，不動 CODEOWNERS：誰審哪一塊是組織的決定。

**ADR-0006 的「技能內容原樣帶過」多了一個組裝期的例外。** 存下來的那一則 turn 仍然是原樣（ADR-0002 沒有被動到），改變的只有它在後面幾輪被帶進提示詞的方式。取用它的那一輪照樣拿到完整內容。

**被遮蔽的內容仍然搜尋得到，而且可能在下一輪原樣回來。** 遮蔽只管它以對話的身分被帶進提示詞；原始紀錄留著，ADR-0014 又讓每一個 Retrieve 都查記憶，所以下一輪的問題命中它時，它會以「這一輪查到的證據」回到系統那一層、而且是完整的。那不是漏洞，是兩件不同的事：帶著走是沒人要求的成本，查出來是有人問了才給。

**遮蔽後的那一句是中文的。** 和 SDK 其他面向使用者的字串一致。模型讀得懂它說的是什麼。

**每遮一則就重數一次請求。** 和 ADR-0016 的裁切一樣，這是一輪裡純 CPU 最貴的部分。先量再換做法。

**`tool_call_submission` 這個來源字串現在有兩個地方認得它。** Playground 寫它，組訊息的那一層讀它。改名字要兩邊一起改。
