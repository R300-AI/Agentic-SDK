# 19. 主題可以刪掉，不能改寫

Date: 2026-09-23

## Status

Accepted

## Context

ADR-0012 讓記憶把最舊的對話合成成主題，ADR-0016 把主題那一行放進每一次請求的系統提示裡。合起來的結果是：一則主題的那一句話，每一輪都出現在模型看得到的範圍內。

合成是模型做的，所以它會錯。錯的那一句不是錯一次，是每一輪錯一次，而且錯得安靜——沒有任何下游的東西會去質疑它。

刪掉它本身不難。難的是刪掉之後它會長回來：合成它的那幾筆原始紀錄還在，而且仍然是可合成的對象，所以下一次合成又做出同一則。那會變成一件要一直重做的事。

## Decision

**刪一則主題做兩件事：主題消失，合成它的那幾筆原始紀錄不再是可合成的對象。** 只做第一件事等於沒做。

**原始紀錄留著，而且留在搜尋得到的地方。** 被刪掉的是記憶做出的一個判斷，不是發生過的事。刪掉紀錄會讓後面任何人都查不出當初講過什麼。

**原始紀錄也不會回到對話裡。** 它們在被合成的那一刻就不再被當成前文交出去，刪掉主題不會把那件事倒回來。

**只提供看與刪，不提供編輯。** 讀者是場域人員，不是寫這個 Agent 的人。改壞的那一句讀起來通順、內容是錯的，而它每一輪都會進到模型看得到的範圍——比一句明顯錯的更難發現。刪掉是一個看得出結果的動作，改寫不是。

**只有主題能刪。** 原始紀錄是發生過的事，這個功能不是用來改寫它的。拿原始紀錄的識別碼來刪會被拒絕，而不是默默地不做事。

**刪一則不在的主題回報失敗，不回報成功。** 按下去的人下一秒就會再看一次那張清單。

考慮過並否決的做法：

- **提供編輯。** 上面那一段。
- **刪掉主題時一併刪掉原始紀錄。** 那會把「記憶記錯了」變成「這件事沒發生過」。
- **把原始紀錄還原成可以合成的狀態，靠別的方法擋住重建。** 擋住的方法要嘛是記下被刪過的措辭去比對——合成每次的措辭不會一樣——要嘛是記下時間，兩者都比在紀錄上做一個記號脆弱。
- **刪掉之後連帶把那幾筆從搜尋中排除。** 搜尋是它們僅剩的用途。

## Consequences

**原始紀錄上的記號從 `synthesised_into` 換成 `forgotten_topic`。** 兩個記號都讓那一筆退出對話，差別在前者還指得到一則存在的主題，後者指的是一則已經不在的。分成兩個鍵而不是留著一個指向空的識別碼，是因為「被收進某則主題」和「它的主題被刪掉了」是兩件事，而後面要判斷的正是後者。

**只有被那則主題收過的紀錄會被標記。** 合成一定會留下最近的幾筆不收（ADR-0012），那幾筆從來不屬於被刪的主題，所以刪完之後它們照樣可以被合成。刪掉一則主題不會讓這個記憶從此不再學新的東西。

**擋住的是那幾筆紀錄，不是那一句話。** 刪掉之後，同一句話仍然可能從別的紀錄再被做出來——合成一定會留下最近的幾筆不收，那幾筆講的往往是同一件事。工單寫的「不會自己長回來」因此精確的說法是：被它收過的那幾筆不會再做出東西來。要擋住一句話本身，得記下被刪過的措辭再去比對，而合成每一次的措辭不會一樣，那條路比在紀錄上做記號脆弱得多。

**刪除會發一個 `memory_topic_forgotten` 事件，目前沒有人接。** 和 ADR-0012 的 `memory_compacted` 一樣：記憶收一個 `on_event`，把它接到 `Workflow` 的 `event_callback` 上是另一份工單。

**Playground 的面板只在承接前文的 Agent 上出現。** 只看這一段對話的 Agent 照設計就不記得任何事，給它一個「它記得什麼」的面板是給一個關於空集合的面板。

**面板讀的是整條流程的記憶，不分對話。** 主題屬於流程；看它記得什麼的人是在看全部，不是在看其中一段對話。

**`memory_admin` 每一次呼叫都重新開一個 `FileMemoryStore`。** 它從磁碟讀，所以看到的是當下的狀態，包括別的行程剛寫進去的。代價是每次都重讀一次目錄；主題的數量級是十位數，先量再換做法。
