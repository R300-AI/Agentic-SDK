# 9. 說話是選擇，不是預設

Date: 2026-09-14

## Status

Accepted

## Context

訪客從 AI Hub 畫廊點進一個語音 Agent，載入完成的瞬間畫面就寫著「聆聽中，直接開口就好」，麥克風已經開著。要打字得先找到輸入列右側那顆鍵盤圖示。

這些人不是自己安裝了一個語音助理，而是在別處看到一張卡片點進來的——可能在辦公室、在通勤路上、在別人旁邊。被要求說話的人若當下不方便，會直接關掉，而那個成本收不回來；想用語音的人多按一下並不會流失。

同時，畫面中央只有一句「你想從哪裡開始呢？」，起始問題是空的。把掛著的技能自動變成可點的起始問題看似順手，但要同時支援語音輸入就得另造一個模組——語音沒有「可點的按鈕」這個概念，兩者的輸入模型不同。這個代價現在不划算。

## Decision

**第一畫面不主動開啟麥克風。** 預設用打字；切換到語音是一個看得懂的動作，並在那個入口說明語音的好處（開口就能打斷）。

**起始問題維持現狀。** 沒有設定就顯示「你想從哪裡開始呢？」。不從技能自動生成——那需要一個同時理解「可點選項」與「語音輸入」的新模組，而這兩種輸入模型不同。

**設了 `disable-model-invocation` 的技能不會出現在任何由平台提議的清單裡。** 該欄位的語意是「不由模型自選」，而平台替使用者提議的建議在性質上接近模型自選；使用者仍可用 `/名稱` 直接叫用。

## Consequences

語音 Agent 的第一畫面與純打字的 Agent 一樣，兩者的差別只在輸入列多一個入口。語音的能力說明從「預設打開之後才講」移到「選擇之前就講」。

訪客仍然看不出這個 Agent 掛了哪些技能——那個問題還在，只是不用起始問題來解。要解就得先決定「可點選項」與「語音輸入」如何共存，那是一個模組層級的決定。

這份決議是在沒有使用者經驗藍圖可對照的情況下做的（`playground/visual-audit/README.md` 引用的三份檔案不在任何本機庫內）。藍圖到手時，這裡是要覆核的第一份文件。
