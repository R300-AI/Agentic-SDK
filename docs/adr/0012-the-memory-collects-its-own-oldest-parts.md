# 12. 把舊對話收成主題是記憶層自己的事

Date: 2026-09-22

## Status

Accepted

## Context

晶片上的端點 context window 比雲端小一個量級以上，而 `InContextMemory` 把整段對話原封不動交給每一個模組。對話一長就爆，使用者的感受是講到一半 agent 突然變笨或直接壞掉，而且不知道為什麼。

要收掉舊的部分，第一個問題是這件事歸誰。看起來最自然的答案是 Reflect——Park 等人 2023 年那篇論文裡的 reflection 就是把累積的觀察合成更高層的記憶，而這個 SDK 的核心概念取自那篇論文。但這條路走不通：`Workflow` 上只有一個 `reflect` 欄位，一條流程只掛得了一個反思模組。把合成做成 Reflect 模組，等於「要壓縮就不能檢查回答有沒有依據」，兩個能力互相排擠。

第二個問題是判斷的時點。兩家標竿在這裡一致：壓縮是自動的，接近門檻就發生，模型不選也不知道。Anthropic 的 compaction 在請求要送出時依當下的用量觸發，它的 context editing 同樣是設定驅動、不經模型判斷。

## Decision

**合成歸記憶層自己，不佔用任何模組的位置。** Reflect 那一格留給它原本的工作。合成也不進 `CrossContextMemory` 協定——不是每一種記憶都做得到這件事，`InMemoryStore` 就沒有端點可以呼叫。能力靠有沒有 `compact` 這個方法判斷，和 `Workflow.converse()` 判斷感知模組會不會聽（`hear` 與 `pending_input`）是同一個手法。

**判斷的時點是記憶層要把內容交給模組的那一刻**，也就是 `as_openai_messages()`。那是記憶的出口，用量在那裡才算得準；更早的時點（例如每次訪問模組之前）還沒組出要送的東西。這也表示流程層不必問「這個記憶壓不壓得了」——壓得了的自己會壓，壓不了的什麼也不會發生。

**從最舊的往回收，收到用量回到門檻以下為止。** 剛講過的話是下一個回答要用的，所以最後才動它；最近兩則一律不動。一趟沒有讓用量下降就停手，把超出的內容照樣交出去——那比對著端點反覆呼叫好。

**被收走的原始紀錄留著，只是不再以對話的身分交出去。** 它們在磁碟上、在搜尋得到的範圍內，只是標記為已被某個主題涵蓋，不再出現在交給模組的對話裡。主題本身補在它們原本的位置上，所以收掉之後沒有東西憑空消失。

**既有主題已經涵蓋的，更新它而不是新增一則。** 更新的意思是拿既有內容加上新的部分重新合成一次，不是接在後面——接在後面會讓主題每次都變大，而對話永遠回不到門檻以下。這一點是被測試逼出來的。

**主題帶一句描述，索引是所有描述的集合，不另外存。** 每次從主題讀出來重算，所以它不會和主題說的話走樣。約 150 字元是給合成那一步的準則，這裡不強制截斷——截掉一句話比留著一句長的更糟。

**記憶自帶端點設定。** 把舊對話收成一句話比回答問題容易，所以場域可以把它指到一個更小更便宜的端點，不必和行動共用。

**壓縮預設關閉。** 沒有設門檻就什麼也不會發生，既有的流程行為不變。

考慮過並否決的做法：

- **做成 Reflect 模組。** 一條流程只掛得了一個反思模組，會和檢查回答的能力互相排擠。
- **焊在 `Workflow` 裡。** 換不掉。做在記憶層則換一個記憶實作就換掉了整套策略，而記憶本來就是可替換的。
- **直接刪掉舊的原始紀錄。** 那會讓「僅供搜尋的原始紀錄」這一層消失，也讓日後換一種合成方式無從重來。
- **讓模型決定什麼時候壓縮。** 兩家標竿都不這樣做，而這裡的端點是小模型，多問一次只是多花一次呼叫。

## Consequences

**token 是估的，不是數的。** OpenAI 相容端點沒有統一的計數介面（Anthropic 有 `count_tokens`，這裡沒有），所以預設用一個標明是估算的算法：CJK 字元約一個 token，其餘約四個字元一個。要精確的部署自己傳一個計數器進來。門檻因此是一個約略的界線，不是硬上限——真正的硬上限屬於流程層，是另一份工單。

**一次壓縮是一次模型呼叫，更新既有主題是兩次。** 發生在使用者等回答的時候，所以那一輪會變慢。門檻設得太低會讓每一輪都壓一次。

**Q49 說的流程層能力偵測在這個位置上用不到。** 那條決議假設由流程層觸發；判斷點定在記憶層出口之後，壓得了的自己會壓。能力偵測這個手法仍然是對的，只是用在需要問的人身上，而流程層目前不需要問。

**索引還沒有被送進提示詞。** 主題本身補在對話裡，所以資訊沒有掉；但把索引放進系統提示那一層、讓規劃看得到有哪些主題可查，屬於優先級棧那一份工單。

**門檻本身就是開關，沒有另一個「啟用」旗標，也沒有預設值。** 不給數字就什麼也不會發生。工單寫的「啟用之後門檻才有預設值」是宣告層的形狀——那一層要多一個明確的開關與一個預設數字，屬於接線那一份工單。

**壓縮的事件要應用程式自己接。** 記憶收一個 `on_event`，但沒有人把它接到 `Workflow` 的 `event_callback` 上，所以 Playground 的推論訊息目前看不到壓縮。接線同樣屬於另一份工單。

**索引還沒有人讀。** `index_lines()` 讀得出來，但把它送進系統提示那一層是優先級棧那一份工單。詞彙表對「索引」的描述寫的是目標狀態，不是現在的行為。

**既有的文字相似度在中文上等於沒有。** `search()` 用的 `_tokenize` 以 `\W+` 切詞，一整句中文會切成一個 token，所以兩句中文的 Jaccard 永遠是 0.0——這個限制在這次之前就存在，也不只影響記憶。這次沒有動它：改那個切法會改變全庫的搜尋結果。主題比對因此自己帶一套比較方式，非 CJK 照詞切、CJK 走相鄰字元對。

**同一段對話的主題只有那一段看得到。** 主題帶著它被合成時的那一段對話的識別碼，所以另一段對話在 `turns` 裡看不到它，要靠搜尋。這和原始紀錄的規則一致。
