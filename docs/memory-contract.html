Memory Contract

這一頁定義 workflow 節點之間共享資料的最小公開契約。它不是內部資料結構教科書，而是文件站所有範例與模組規格共同依賴的對接面。

如果某個模組需要模型能力，那個模組仍遵守 OpenAI SDK form 的接入規格；但模型 client 本身不直接寫入 memory，真正寫入或讀取 memory 的是各功能模組。

公開 memory 慣例

Prose-first 契約

本頁只定義跨模組共享的 key 與意義，不暴露當前程式內部實作細節。

最小 key 集

README 與文件站示例都以同一組最小 key 命名，避免每頁自行發明欄位名稱。

可擴充但不可漂移

你可以在專案內加自己的 key，但不應任意改寫這組最小公開 key 的語意。

最小公開 key

Key 由誰寫入 誰會讀取 內容說明
input 呼叫端 Perceive 原始使用者輸入或上游系統傳入的主要問題。
perceived_input Perceive Plan、Retrieve、Action 感知後的整理結果，可是原文直通，也可以是較乾淨的理解版本。
plan Plan Retrieve、Action、Reflect 規劃後的路徑、步驟或執行意圖。
query Perceive 或 Plan Retrieve 供檢索模組使用的查詢文字或查詢條件。
retrieved_items Retrieve Action、Reflect 命中的知識條目、文件片段或整理後的檢索結果。
draft_answer Action Reflect 尚未最終提交的候選答案，供反思模組評估。
final_answer Action 或 Reflect 呼叫端 流程最終輸出的回答內容。
reflection Reflect Plan、Action 對上一輪答案的評估結果、修正建議或重試訊號。

典型流向

input
  -> perceived_input
  -> query
  -> retrieved_items
  -> draft_answer
  -> final_answer

若 workflow 納入 planner，plan 會出現在 perceived_input 與 query / draft_answer 之間；若納入 reflect，reflection 會作為下一輪規劃或重寫輸入。

這組 key 是文件站與範例的一致命名。各模組頁會在此基礎上補充自己的讀寫要求。
